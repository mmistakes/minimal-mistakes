Clean code is code that is easy to read, easy to change, and clearly intentional. Bad code compounds: teams slow down, fear changes, and spend more time decoding than delivering.

There is no single definition, but recurring traits include:

- Readable by other people (and by you in six months)
- Does what it says; no surprises
- Minimal accidental complexity
- Covered by tests so you can change it safely
- Expresses the author's intent without needing a tour guide

The Boy Scout Rule: leave the campground cleaner than you found it. Small, continuous cleanups beat big-bang rewrites.

Professionalism is not speed-at-all-costs. Wading through mess is slower than writing clean code in the first place.
